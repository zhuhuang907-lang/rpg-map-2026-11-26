# 「局面」操作页核验报告（2026-11-24）

- 核验对象：`web/game.src.html`，工作分支 `zcode/scan`（基线 R-266 f44a0bc＋本地未推的月结/停用改动）。
- 核验方法：读代码定位＋浏览器里构造存档直接调函数（Playwright，`web/index.html`），不猜现象。
- 结论：候选 4 条里 **3 条成立、1 条需更正**（第 2 条前半不成立、后半成立）；另有 4 项照原样核验为「不报」。

## 一、成立：threatAct 先占当月一次、后校验，点空选项白耗机会

**位置**：`web/game.src.html:10040` `threatAct`，第 10043 行：

```js
s.threatDone = s.threatDone || {}; if (s.threatDone[T.name] === ym) { ORGMSG = '这个月已经定了主意'; return null; } s.threatDone[T.name] = ym;
if (act === 'hold') { if (D.kind !== 'local' && D.kind !== 'realm' && D.kind !== 'army') { … return null; }
```

`threatDone[T.name] = ym` 写在所有分支校验之前；`hold`（守军不详 `!r`）、`yield`（身份不符）、`fort`（没有行情底账 `needEcon()`、募不起十人）失败返回时，当月机会已经记掉了。

**复现（浏览器实测）**：构造无经济底账、现钱 0 的平民存档，`rebelThreat` 给一个「测匪」；点「散财募勇、结寨自保」→ 返回 null、`threatDone['测匪'] = 13203`（当月）；再点「举家逃难」→ 返回 null、提示「这个月已经定了主意」。
**玩家可见后果**：点了当下办不到的那一项，本月剩下的守/逃/投都不能再选，只能等下月。
**严重度**：中（每月一次的机会被误扣；不是常态但可稳定复现）。
**修法方向**：把写 `threatDone` 挪到每个分支成功之后（或统一在函数末尾按「是否真办成」写），失败路径不记。

## 二、部分成立（需更正）：诏狱只清了一半身份，辖区与官阶还在

**位置**：`11826` `impeachAct`；诏狱分支 `11830-11831`：

```js
try { shedIdentity(s, '下狱', { land: 'keep', biz: 'keep' }); } catch (_) { }
s.jail = { where: '诏狱', charge: I.charge, since: timeText(s.clock) }; s.impeach = null;
```

**更正原判断**：「只设 s.jail，未清 s.career.office」不成立——`shedIdentity`（11662）确实清了 `career.office`（移到 `career.left`）、收了兵（非一方之主）、清了地盘、`s.rank=null`、`s.org/s.gov=null`。浏览器实测：下诏狱后 `career.office` 为空、forces 0、territory 0。

**但残留是真的**：
1. `career.rank` 没清（实测仍是「正四品」）。
2. **`protagonist.role` 没清**（仍是「知府」）。`identityOf`（2876）在没有 office 时会拿 role 当官身（`offTxt = officeHeld || (ID_LOCAL.test(roleOwn) … ? roleOwn : '')`），于是 `myDomain(s).kind` 仍是 `local`——实测下诏狱后 `dom: local`。
3. 因此在押时局面页照旧渲染出 **赋税 3 个按钮、工程 6 个、城务 8 个、商业 5 个**（浏览器实测 DOM 计数），人关在诏狱里还能定赋税、修工程、管城、走货。

**另一个入口更彻底**：记账那条 `15830`（AI 报 `jail.in=true`，如被下狱、被拿）只写 `s.jail = { where, charge, since, cost }`，**什么都不清**——官职、兵、地盘、身份全留着。走这条路进监，局面页所有面板原样在，第三类问题（在押可操作）全部可达。实测里「操练/赌钱/讨饷/保题」「冲锋/逃散/投敌」这些按钮要靠兵籍或队伍才渲染，走诏狱入口时会消失（`shedIdentity` 收了兵），但走记账入口时都还在。

**玩家可见后果**：诏狱只封了「本职公务」那一块，地方官的全套操作还在，与「人进了诏狱，官印交了」的正文和 `s.jail` 提示直接矛盾。
**严重度**：高（状态与权限不一致，玩家可在狱中继续执政）。
**修法方向**：下诏狱时把 `protagonist.role` 里的官职摘掉（或写入「待罪」），并清 `career.rank`；或在 `identityOf`/`myDomain` 里 jailed 时强制 `admin='none'`；渲染层在押时只出押牢面板；`15830` 记账入口进监时走同一个 `shedIdentity` 收权流程。

## 三、成立：事件分发只有「江湖」一组拦在押，其余六类操作在押仍可执行

**位置**（均在 `web/game.src.html`）：

- **无拦截**：
  - `17497` `data-threat`（御寇：守/降/逃/募勇/投义军）
  - `17564` `data-fisc` / `data-work`（定赋税、盐法、铸钱、徭役、修工程）
  - `17571` `data-camp` / `data-merc` / `data-priv`（操练、告假、赌钱、讨饷、保题、吃空饷；走货、赊货、雇伙计、打点关卡；私下日子）
  - `17572` `data-soldier`（冲锋、逃散、投敌、推戴）
  - `17575` `data-land`（收租、加减租、置田、放债）

**实测**：在押状态下直接调 `fiscPolicy(s,'tax','重')` → 成功改为「重」；DOM 上赋税 3、工程 6、城务 8、商业 5 个按钮都在。
**玩家可见后果**：关在牢里照样理财、练兵、置田、传檄，`s.jail` 提示「能做的只有托人、打点、写状子、熬」形同虚设。
**严重度**：高（面最广）。
**修法方向**：事件分发入口统一加一道 `if (S.jail && !JAIL_OK.has(kind)) { ORGMSG='你还被关着，先想法出去'; return; }`，白名单只留押牢面板（越狱/赎身/说话）与「托人、打点、写状子」类。

## 四、成立：在押时身份行动建议仍给「升堂审案」「操练」等

**位置**：`5008` `roleActions`、`10001` `whoHtml`；两者都没有 `s.jail` 分支。
**实测**：诏狱中的「知府」拿到的建议仍是——「升堂，把积压的案子审几件」「下乡察看农事」「传捕快来，问近来的盗案」「查库里的钱粮」「请本地几位士绅」；`whoHtml` 身份仍写「知府」。正文提示（13592）却写「能做的只有托人、打点、写状子、熬」。
**玩家可见后果**：界面引导玩家做狱中做不了的事；点这些建议只是写进输入框，但会诱导玩家按「在外办公」写下一步，随后被推演/正文打回。
**严重度**：低—中（文案与引导层，不直接改账）。
**修法方向**：`roleActions`/`whoHtml` 开头加在押分支，只给「托人、打点、写状子、探监、熬」这类。
